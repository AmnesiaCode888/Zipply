# Модель-классификатор — план реализации

> **Для исполнителя:** выполнить задачи последовательно в текущей рабочей копии и сохранить все существующие изменения пользователя.

**Цель:** добавить настраиваемую недорогую модель-классификатор и единый способ вызывать её для проверок.

**Архитектура:** отдельное строковое поле `classifierModel` хранится вместе с настройками приложения и передаётся в конфигурацию агента. `ChatService.classify` использует это поле для non-streaming вызова без инструментов; основной чат остаётся на прежней модели.

**Стек:** TypeScript, React, Electron IPC уже используется для настроек и агентов; новый IPC-канал не нужен.

**Спецификация:** `docs/superpowers/specs/2026-11-06-classifier-model-design.md`.

## Общие ограничения

- Контролы: строго `border-none`; для элементов управления фокус не меняет цвет или границу.
- Тени и свечение запрещены: `shadow-none`, `boxShadow: 'none'`, без `drop-shadow` и ореолов.
- Кнопки и контролы используют `rounded-full`; крупные поверхности — `rounded-[20px]`, `rounded-[22px]` или `rounded-[24px]`.
- Сохранять существующее API-совместимое подключение: один API-ключ и текущий Base URL.
- Не изменять поведение обычного чата и не назначать проверки автоматически.
- Не добавлять и не запускать тесты в рамках этого изменения.

## Фокус проверки кода

- Старые настройки без `classifierModel` загружаются с пустым значением.
- Пробелы в ID модели удаляются при загрузке и сохранении.
- Пустой или отсутствующий ID не отправляет запрос и даёт понятную ошибку.
- Вызов использует только classifier model, без tool definitions, и не включает streaming.
- `AbortSignal` передаётся в общий механизм запроса.
