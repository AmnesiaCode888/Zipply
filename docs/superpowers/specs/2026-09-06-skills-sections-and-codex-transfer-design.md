# Архитектурный дизайн: Разделы скиллов, миграция из Codex в Zipply и улучшенный поиск для ИИ

## 1. Контекст и цели

Пользователь поставил задачи:
1. **Система скиллов по папкам и разделам**:
   - Физические и логические папки категорий (системные скиллы по дефолту, инструменты, инженерные, проектные, внешние).
   - Возможность сразу включить или выключить весь раздел целиком.
   - Полная 100% обратная совместимость со всеми сторонними скиллами (`.agents/skills`, `.codex/skills`, `.claude/skills`, `~/.codex/skills`, `~/.agents/skills`, Cursor rules).
2. **Перенос скиллов из раздела Codex в Zipply**:
   - Специальная кнопка в разделе Codex, открывающая модальное окно.
   - Возможность выбрать любые скиллы из Codex (как отдельные `.md`, так и целые папки со скриптами/ресурсами) и перенести их в локальную библиотеку Zipply с сохранением структуры.
3. **Прокачка использования скиллов агентом (ИИ / Zipply)**:
   - Агент всегда четко осознает, что у него есть библиотека скиллов, и знает ее разделы.
   - Структурированная карта разделов в системном промпте.
   - Надежный гибридный поиск (`search_skills`): векторный поиск (при наличии эмбеддингов) + взвешенный полнотекстовый поиск по триггерам, тегам, именам и содержимому.
   - Поддержка фильтрации по категориям в `list_skills(category="...")`.

## 2. Архитектурные решения

### 2.1. Модель разделов и структура хранения

#### Физическая структура `SkillService.getSkillsDir()`
```
skills/
├── core/                  # Всегда активные базовые правила (системный промпт)
├── extra/                 # Дополнительные навыки по разделам:
│   ├── system/            # Встроенные системные навыки (when-stuck, systematic-debugging, continuous-evolution)
│   ├── tools/             # Инструменты Zipply (tool-file-mastery, tool-terminal, tool-grep, tool-web, etc.)
│   ├── engineering/       # Инженерные (tdd, frontend, backend, database, docker, etc.)
│   └── custom/            # Пользовательские навыки
├── disabled_skills.json   # Список отключенных навыков
└── disabled_categories.json # Список отключенных разделов целиком
```

#### Классификация и категории навыков (`category / section`)
Каждый навык `SkillItem` расширяется полями:
- `category: string` — идентификатор раздела (`system`, `tools`, `engineering`, `workspace`, `codex`, `custom`, либо имя подпапки).
- `categoryLabel: string` — человекочитаемое имя на русском («Системные», «Инструменты Zipply», «Разработка и архитектура», «Текущий проект», «Codex», «Пользовательские»).
- `categoryIcon?: string` — иконка для UI.

#### Правила классификации сторонних навыков:
1. Если навык найден в `~/.codex/skills` или `.codex/skills` -> категория `codex` («Codex»).
2. Если навык найден в рабочем каталоге проекта (`.agents/skills`, `.skills`, `skills`) -> категория `workspace` («Проект»).
3. Если навык в `~/.claude/skills` или `CLAUDE.md` -> категория `claude` («Claude / Инструкции»).
4. Если навык лежит во вложенной папке `skills/extra/<subfolder>/` -> категория `<subfolder>`.
5. Если в Frontmatter явно указано `category: ...` — используется оно.

> [!IMPORTANT]
> Обратная совместимость: если на диске лежат старые плоские файлы в `skills/extra/*.md` без подпапок, они автоматически классифицируются в соответствующие разделы по префиксу или тегам (например, файлы `tool-*` -> `tools`, `when-stuck` -> `system`, прочие -> `engineering`/`custom`). Ни один существующий файл не теряется.

### 2.2. Массовое переключение разделов (Bulk Toggle)

В `SkillService` и IPC API добавляются методы:
- `SkillService.toggleCategoryEnabled(categoryKey: string, enabled: boolean): { success: boolean; count: number }`
  - Добавляет/удаляет все навыки этой категории в `disabled_skills.json`.
  - Сохраняет статус категории в `disabled_categories.json`.
- В UI в шапке каждого раздела отображается переключатель «Вкл / Выкл весь раздел» со счетчиком (например, «8/8 активно»).

---

### 2.3. Модальное окно миграции из Codex в Zipply (`CodexTransferModal`)

#### Функционал:
1. В шапке раздела **Codex** появляется кнопка с иконкой: **«Перенести в Zipply»**.
2. Открывается модальное окно:
   - Список всех обнаруженных скиллов Codex (с чекбоксами «Выбрать все» / по отдельности).
   - Индикация типа навыка: одиночный файл (`.md`) или пакетная папка (со скриптами, `scripts/`, `references/`).
   - Выбор целевой категории в Zipply (по умолчанию «Пользовательские» или «Инженерия», либо создание новой папки).
   - Выбор режима: «По требованию (Extra)» или «В памяти всегда (Core)».
   - Опция: «Копировать со всеми вложенными файлами и зависимостями».
3. При нажатии «Перенести»:
   - Файлы/папки безопасно копируются в `skills/extra/<category>/` с валидацией Frontmatter.
   - Автоматически обновляются кеш эмбеддингов и список скиллов.
   - Показывается уведомление об успешном переносе.

### 2.4. Прокачка понимания и поиска скиллов для ИИ

#### Структурированный каталог в системном промпте (`AgentRunner.ts` -> `SkillService.getStableSkillsCatalogPrompt`):
Вместо плоского списка ИИ получает структурированное древо разделов:
```xml
=== КАТАЛОГ НАВЫКОВ ПО РАЗДЕЛАМ (Онтология знаний) ===
У тебя есть встроенная библиотека проверенных инженерных руководств и правил.
Ты ОБЯЗАНА использовать навыки перед сложными задачами или при возникновении трудностей:
<skills_ontology>
  <category id="system" title="Системные правила и выход из тупика">
    <skill name="when-stuck" desc="Пошаговый протокол действий, когда застряла или что-то идет не так"/>
    <skill name="systematic-debugging" desc="Строгая 4-фазная методика отладки"/>
  </category>
  <category id="tools" title="Мастерство инструментов">
    <skill name="tool-file-mastery" desc="Безопасная работа с файлами, правки без перезаписи"/>
    <skill name="tool-terminal-mastery" desc="PowerShell, фоновые команды, чтение вывода"/>
  </category>
  <category id="engineering" title="Разработка и стек">
    <skill name="test-driven-development" desc="Методология TDD, красная-зеленая шкала"/>
    <skill name="frontend-modern-web" desc="React, TypeScript, Electron UI"/>
  </category>
</skills_ontology>
Для изучения любого навыка вызови: `read_skill(skill_name="...")`.
Для поиска по ключевым словам или теме вызови: `search_skills(query="...")`.
Для просмотра всех навыков раздела вызови: `list_skills(category="...")`.
```

#### Улучшенный гибридный поиск (`SearchSkillTool` & `SkillService.searchSkillsAsync`):
1. **Векторный поиск**: косинусное сходство через кешированные эмбеддинги.
2. **Лексический ранжир (BM25/Fuzzy)**:
   - Совпадение по `triggers` (вес x3.0).
   - Совпадение по имени и категории (вес x2.0).
   - Совпадение по тегам и маскам файлов `globs` (вес x1.5).
   - Совпадение по тексту описания и инструкций.
3. **Возврат метаданных**: инструмент возвращает имя категории, релевантность (%), причину совпадения и команду для мгновенного чтения.

## 3. План верификации

1. **Тест структуры разделов**: сканирование `getAllSkills()` возвращает правильные категории для дефолтных, сторонних (Codex, Workspace) и кастомных навыков.
2. **Тест массового включения/выключения**: переключение раздела отключает все его навыки и обновляет `disabled_categories.json`.
3. **Тест переноса из Codex**: модальное окно переносит как одиночный `.md`, так и папку со скриптами в `skills/extra/<category>/`.
4. **Тест поиска и промпта**: вызов `search_skills` корректно ранжирует навыки по запросам (например, "react", "terminal powershell", "stuck in loop").
5. **Тест компиляции**: `npm run build` / TypeScript тайпчек проходит без ошибок.
