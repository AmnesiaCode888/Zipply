# Hermes Agent и расширения Zipply

26 ноября 2026 года. Разбор основан на документации и исходниках ветки `main` Nous Research и на текущем рабочем дереве Zipply. Доступность в Hermes зависит от интерфейса, конфигурации и версии установленной сборки.

После этого разбора проверена локальная версия Hermes 0.15.1 и сопоставлены ещё шесть харнесов. В установленной версии каталог доступен из CLI, а карточка `manage_connections` описана для более нового кода. Сравнение также уточняет приоритет Zipply. [Сравнение харнесов](2026-11-26-agent-harness-comparison.md).

## MCP от запроса до первого вызова

1. `manage_connections` принимает имя цели и тип. Для установки MCP имя сверяется с каталогом, для включения и авторизации используется список уже настроенных серверов. Схему транспорта и параметры установки выбирает Hermes по записи каталога или по сохранённым настройкам. Источники: [валидация целей](https://github.com/NousResearch/hermes-agent/blob/main/tools/connectors/targets.py), [MCP-операции](https://github.com/NousResearch/hermes-agent/blob/main/tools/connectors/mcp.py).
2. Операция привязана к сессии и вызову инструмента. Hermes подготавливает данные, отправляет карточку и ждёт ответа, отмены или тайм-аута. Пользователь нажимает подключение и проходит OAuth в браузере, если он нужен. При отказе токена или отмене до сохранения прежняя конфигурация остаётся действующей. Источники: [жизненный цикл операции](https://github.com/NousResearch/hermes-agent/blob/main/tools/connectors/run.py), [карточка подключения](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp#catalog-one-click-install-for-nous-approved-mcps).
3. После авторизации обновляется каталог инструментов. При сбое обнаружения Hermes сообщает, что авторизация есть, а инструменты пока недоступны. Повторное обнаружение использует сохранённую авторизацию. Состав инструментов можно ограничить через фильтры сервера. Изменения `tools/list_changed` приводят к обновлению каталога. Для сервера с `lazy: true` после первичного подключения могут использоваться схемы из кеша, а живое соединение откладывается до вызова. Источник: [обнаружение, фильтры и подключение MCP](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp).

Hermes различает размещённый коннектор аккаунта и сервер MCP. Имя сервиса может совпадать в обоих каталогах. `manage_catalog` обслуживает плагины и навыки, принимает пары `{kind, id}`, а хост определяет источник, версию и профиль. Путь через эту карточку относится к Desktop. Для большей библиотеки Zipply это аргумент в пользу стабильных идентификаторов и общих операций под интерфейсом чата и страницей «Расширения». Источники: [маршрутизация `manage_connections`](https://github.com/NousResearch/hermes-agent/blob/main/tools/connectors/tool.py), [реализация `manage_catalog`](https://github.com/NousResearch/hermes-agent/blob/main/tools/connectors/catalog_tool.py), [ограничения по интерфейсам](https://hermes-agent.nousresearch.com/docs/reference/toolsets-reference).

Доверие на уровне MCP у Hermes по умолчанию `full`. При `untrusted` подтверждение требуется для инструментов без серверного `readOnlyHint: true`. Для Zipply предлагается сохранить собственную политику подтверждений MCP, поскольку `readOnlyHint` объявляется сервером, а управление подключением и допуск отдельных вызовов имеют разные последствия. [Настройки доверия Hermes](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference), [адаптер Zipply](../../../src/main/agent/mcp/McpToolAdapter.ts).

## Навык и его инструменты

Hermes сначала показывает метаданные, затем читает основной файл и открывает отдельные `references/` по мере необходимости. `metadata.hermes.requires_tools` и `requires_toolsets` управляют видимостью навыка по доступности инструментов. `fallback_for_tools` и `fallback_for_toolsets` показывают запасной навык при отсутствии основной возможности. `required_environment_variables` даёт локальному CLI возможность запросить недостающий секрет при загрузке навыка. Эти поля и правила размещения относятся к Hermes. Источники: [загрузка навыков](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills#progressive-disclosure), [условная активация](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills#conditional-activation-fallback-skills), [Agent Skills](https://agentskills.io/specification).

Для навыка с собственным API Hermes поддерживает переносимый пакет `plugin.json` с `skills/` и `mcp.json`. Навык пакета получает имя `plugin:skill` и доступ только на чтение. Описанный Hermes набор поддерживает stdio и Streamable HTTP. Отдельно нативный Python-плагин регистрирует обработчики инструментов, навыки, команды и хуки через `register(ctx)`. У курируемых записей каталога закреплён коммит пакета. Версия пакета фиксирует его файлы, а набор инструментов удалённого MCP может изменяться во время работы. Источники: [Portable Agent Plugins в Hermes](https://hermes-agent.nousresearch.com/docs/developer-guide/plugins#portable-agent-plugins-v1-packages), [нативные плагины](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins), [каталог](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugin-catalog).

Для внешних навыков Skills Hub сохраняет сведения об источнике и хеше. Для стороннего URL или GitHub импортируются `SKILL.md` и упомянутые в нём файлы из допустимых папок. Hermes проверяет собранный пакет до установки. Для Zipply это ориентир при расширении `SkillImportService`. Ссылки `metadata.zipply_tools` уже подходят для процедуры поверх установленных возможностей. Для поставки нового инструмента вместе с навыком нужен пакет и существующий исполнитель MCP. Источники: [Skills Hub](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills#skills-hub), [связи инструментов Zipply](../../../src/main/agent/skills/SkillToolBindings.ts).

Hermes обнаруживает `.hermes/skills/` и `.agents/skills/` в ближайшем Git-корне. Перед включением проектных навыков запоминается доверие к репозиторию, а результат проверки навыка кешируется по хешу содержимого. Проектные навыки имеют приоритет над одноимёнными навыками профиля. Куратор оставляет файлы репозитория в ведении проекта. Это полезный вариант совместимости с навыками Zipply из `.agents/skills/`. [Проектные навыки Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills#project-local-skills).

### Отложенная загрузка инструментов

Hermes оставляет рабочий набор встроенных инструментов в контексте. Для отложенных инструментов использует `tool_search`, `tool_describe` и `tool_call` в пределах разрешённого каталога сессии. При росте списка описания сокращаются до имён или сводки серверов, а точная схема доступна по запросу. Вызов через этот слой проходит через обычный исполнитель, включая проверку аргументов и разрешений. `search_tools` Zipply уже решает поиск ID для автора навыка. Сейчас `runAgent` добавляет все схемы инструментов явно выбранного MCP-сервера. Чтобы получить эффект Hermes, нужно отложить именно регистрацию схем, сохранив текущий `ToolExecutor` для вызовов. Источники: [Hermes Tool Search](https://hermes-agent.nousresearch.com/docs/user-guide/features/tool-search), [поиск в Zipply](../../../src/main/agent/skills/SearchExtensionToolsTool.ts), [сборка инструментов Zipply](../../../src/main/agent/index.ts).

## Как Hermes учится на опыте

Встроенная память хранит короткие факты о среде в `MEMORY.md` и предпочтения пользователя в `USER.md`. Их снимок входит в контекст сессии. Процедуры хранятся как навыки и открываются по задаче. Модель пересматривает эти записи, поэтому новые версии модели для такого обучения не требуются. [Постоянная память Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).

| Механизм | Что делает | Практический вывод для Zipply |
| --- | --- | --- |
| `/learn` | Собирает материал из текущей беседы, указанных файлов и документации обычными инструментами. Создаёт или уточняет процедуру. | Использовать `propose_skill` как точку записи и добавить изменение существующего навыка по базовой ревизии. |
| `/refine` и фоновый review | Запускает отдельный проход после накопления достаточно пользовательских ходов или итераций инструментов. Для навыков ищет повторяемый процесс, подтверждённое исправление или поправку пользователя. Для правок фоновой модели требуется прочитать целевой файл. Список разрешённых инструментов проверяется при вызове. | Запускать отдельный проход после `run_summary`, брать минимум доказательств из текущего запуска, разрешить только чтение выбранных навыков и создание черновика. |
| `write_approval` | По умолчанию `skill_manage` пишет сразу. Опциональное подтверждение сохраняет операции до принятия, с просмотром diff. Этот переключатель охватывает операции `skill_manage`. | Для фона оставить черновики. Привязать публикацию к ревизии и проверять конфликт в момент принятия. |
| Curator | Учитывает происхождение и использование. Переводит давно не использовавшиеся навыки в архив, поддерживает закрепление и блокировку. Умеет восстановить состояние через журнал и сохранённое содержимое. Объединение моделью включается отдельно. | Хранить ID запуска, активную ревизию, предыдущую версию, использование и результат проверки перед включением автоматической публикации. |

Источники: [явное обучение](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills#learning-a-skill-from-sources-learn), [сигналы review](https://hermes-agent.nousresearch.com/docs/user-guide/features/hooks), [исходник review](https://github.com/NousResearch/hermes-agent/blob/main/agent/background_review.py), [проверки `skill_manage`](https://github.com/NousResearch/hermes-agent/blob/main/tools/skill_manager_tool.py), [Curator](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator).

Review по умолчанию использует основную модель с повтором контекста беседы. При маршрутизации к другой модели использует сокращённое представление. Для встроенного локального рантайма документация описывает очередь в памяти, которая ждёт простоя и теряет отложенные задания при выходе приложения. Для Zipply лучше использовать сохраняемый минимум свидетельств. Порог запуска ограничивает стоимость, а качество предложенной процедуры оценивается отдельно на другом примере. Нынешний `propose_skill` получает решение от модели во время запроса. Формат и путь черновика валидируются, пригодность процедуры не оценивается автоматически. Источники: [режимы фонового review](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory#running-the-review-on-a-cheaper-model-auxiliarybackground_review), [итог запуска Zipply](../../../src/main/agent/core/AgentRunner.ts), [хранилище черновиков Zipply](../../../src/main/agent/skills/SkillProposalStore.ts).

## Очерёдность изменений Zipply

1. **Подключение из разговора.** Вынести регистрацию и подключение из IPC в общую операцию main process. Существующий экран и новый вызов агента используют её вместе. Модель задаёт ID каталога, приложение показывает транспорт и область подключения, секреты идут в `SecretStore`. Отдельно возвращать `connected`, `authorized_tools_unavailable`, отказ и отмену. Первый сценарий можно реализовать на записи каталога Streamable HTTP без учётных данных. OAuth и запуск локального процесса добавляются через свои маршруты.
2. **Общий поиск и использование в том же запуске.** Пометить зарегистрированный сервер как доступный, требующий подключения или отключённый. Обновлять снимок возможностей чата после одобрения. Находить один инструмент, подгружать его текущую схему и вызывать через `McpToolAdapter` и `ToolExecutor`. На повторных запусках использовать сохранённую область доступа. Явный выбор MCP и старые ссылки `ExtensionRef` продолжают работать.
3. **Импорт навыков и пакетов из каталога.** Добавить предварительный просмотр, указание версии и источника. Начать с текстовых навыков с `references/`, затем разрешить декларативный пакет со схемой MCP и пространством имён навыков. Создание собственного MCP-сервера остаётся задачей разработки кода и его регистрации. Нативные расширения с собственными обработчиками требуют отдельно определённого интерфейса исполнения.
4. **Обучение и обслуживание библиотеки.** Дать `/learn` доступ к созданию и обновлению проектной процедуры через один сервис. Сохранять версию, diff и откат. Затем слушать исходы запуска, отбирать подтверждённые уроки, оценивать их на новых задачах и включать автоматическую публикацию по настройке проекта. Первая оценка сравнивает результат с текущей версией, отдельно считает лишние срабатывания и затраты.

Проверка первого шага начинается с просьбы подключить каталог документации и сразу задать ему вопрос. Пользователь подтверждает подключение в карточке и получает ответ в текущем чате. Отмена освобождает ожидание без сохранения новой конфигурации. Сбой обнаружения отображается отдельно и допускает повтор. Поиск установленного навыка или сервера показывает его состояние и доступное действие.
