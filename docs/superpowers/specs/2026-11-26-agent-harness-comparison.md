Срез на 26 ноября 2026 года. Проверены локальные версии, справка CLI, публичные руководства и доступные исходники. Таблица ниже описывает актуальные публичные реализации. Результаты запуска установленных программ приведены отдельно. Проверок с живым аккаунтом или моделью в рамках этого разбора не было.

## Одна задача с уже подключённым MCP

Пользователь просит найти пояснение в подключённой базе документации или посмотреть уже доступную задачу в трекере. Здесь должны сработать четыре независимые вещи. Приложение знает адрес и способ авторизации сервера. Запуск получает разрешённый набор. Модель узнаёт о нужном инструменте. Исполнитель применяет правила к конкретному вызову.

| Харнес | Как сервер настраивают | Что происходит при обычном запросе в чате |
| --- | --- | --- |
| **Codex** | `codex mcp add` или конфигурация. CLI имеет `/mcp` для статуса. App Server перечисляет инструменты и состояние авторизации независимо от диалога и умеет перечитать конфигурацию. | В `main` `tool_search` ищет BM25 по отложенным метаданным и отдаёт параметры найденных инструментов для следующего запроса модели. Появляется обычный вызов инструмента. Режимы исполнения зависят от провайдера и модели. [Настройка MCP](https://developers.openai.com/codex/mcp) · [Tool Search](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/tool_search_spec.rs) · [App Server](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md). |
| **Claude Code** | `claude mcp add` поддерживает личную настройку для репозитория, общую `.mcp.json` или пользовательскую область. `/mcp` управляет состоянием и входом. Коннекторы claude.ai и плагины могут поставлять свои серверы. | Рантайм подаёт рабочий набор и откладывает остальные схемы. `ToolSearch` находит нужные схемы, после чего модель вызывает MCP обычным способом. Для установки и вызова применяются отдельные правила. В `/mcp` сервер остаётся видимым даже при сбое связи и показывает причину. [MCP и Tool Search](https://code.claude.com/docs/en/mcp). |

Новые инструменты после успешной установки через карточку доступны в том же ходе. [MCP](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp) · [Tool Search](https://hermes-agent.nousresearch.com/docs/user-guide/features/tool-search) · [Проверка доступности](https://github.com/NousResearch/hermes-agent/blob/main/tools/connectors/gateway/config.py). |
| **OpenClaw** | Сервер хранится в `mcp.servers` и управляется через настройки Gateway или `openclaw mcp add`. В прямом чате модель может открыть авторизацию для MCP, которому нужно войти в аккаунт. Документация в этом маршруте просит отправить следующее сообщение после OAuth. | Действуют общий профиль инструментов и фильтры сервера. | **Pi** | Ядро опирается на CLI окружающей среды и расширения. Сервер MCP можно подключить через отдельное расширение. | Агент читает инструкции навыка и использует подходящий CLI либо инструмент расширения. Самая важная разница с Zipply в первом сценарии видна без установки новых пакетов. В Codex и Claude Code модель сама обнаруживает пригодный инструмент среди уже разрешённых в рабочей области. В OpenCode и Gemini это делает рантайм при подготовке возможностей запуска. В Hermes даже расширенный путь с карточкой начинается с сохранённой настройки или записи каталога. Операция подключения сама по себе не решает задачу обнаружения инструмента в новом чате. [Исходник поиска Codex](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/tool_search.rs) · [Реализация установки MCP в Hermes](https://github.com/NousResearch/hermes-agent/blob/main/tools/connectors/mcp.py).

## Две разные просьбы пользователя

**«Подключи этот сервер»** выражает намерение изменить настройки. В конфигурационных харнесах это действие пользователя, команды CLI или клиента приложения. В Hermes модель может инициировать операцию по ID, а форма и сохранение принадлежат хосту. В OpenClaw похожий маршрут может завершиться ссылкой входа и продолжением в следующем сообщении. Ни продолжение в том же ходе, ни текстовая команда установки не являются обязательными свойствами MCP. [Hermes `manage_connections`](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/reference/tools-reference.md) · [OpenClaw MCP](https://docs.openclaw.ai/tools/mcp) · [Codex MCP](https://developers.openai.com/codex/mcp).

**«Найди задачу в Linear»** предполагает использование, когда интеграция уже разрешена. Зрелый маршрут начинается с поиска доступной возможности. При отсутствии авторизации хост может вернуть состояние и действие входа. Когда сервер отсутствует, интерфейс может предложить установку подходящей записи. Если пользователь отменяет подключение, следующий шаг должен использовать имеющиеся возможности или честно обозначить причину. Выполнение `tools/call` с его аргументами остаётся отдельной операцией.

| Что пользователь хочет | Как это устроено в реальных харнесах |
| --- | --- |
| Сохранить способ пользоваться существующими инструментами | Папка `SKILL.md` с описанием применения, шагами, примерами и при необходимости `references/`. Codex и Claude могут выбрать её по описанию. OpenCode перечисляет доступные навыки по метаданным и читает выбранный через `skill`. Gemini загружает выбранный через `activate_skill` с отдельным согласием на открытие каталога. [Agent Skills](https://agentskills.io/specification) · [Codex](https://developers.openai.com/codex/skills) · [OpenCode](https://opencode.ai/docs/skills/) · [Gemini](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/skills.md). |
| Дать навыку локальный вспомогательный расчёт | `scripts/` поставляет исполняемый файл. Навык объясняет, когда его запускать и что принимать на вход. Среда запуска, ограничения и доступ к файлам относятся к инструменту исполнения. Pi широко использует этот вариант с CLI и отдельно позволяет добавлять нативные инструменты через расширения. | Установить процедуру и новый API за один раз | Плагин объединяет несколько компонентов. Claude Code поставляет `skills/` и `.mcp.json`. Hermes поддерживает переносимые `plugin.json`, `skills/` и `mcp.json`. OpenClaw поддерживает совместимые пакеты и собственные плагины. Нативный плагин OpenClaw может объявить дешёвые метаданные инструмента в манифесте и загрузить код отдельно. [Claude](https://code.claude.com/docs/en/plugins/manifest-reference) · [Hermes](https://hermes-agent.nousresearch.com/docs/developer-guide/plugins#portable-agent-plugins-v1-packages) · [OpenClaw](https://docs.openclaw.ai/plugins/manifest). |
| Получать инструкции прямо от поставщика MCP | Расширение Skills over MCP в бета-спецификации публикует метаданные и манифест файлов через `skills/list` и `skills/get`. Claude Code уже описывает поддержку в отдельных конфигурациях. Навык получает пространство имён сервера. Сохранённое одобрение версии связано с набором файлов и их хешами. Это отдельный вариант доставки поверх подключённого сервера. [Спецификация Skills over MCP](https://skills.extensions.modelcontextprotocol.io/specification/beta/skills) · [Claude Code](https://code.claude.com/docs/en/mcp#use-skills-from-mcp-servers). |

Из этого следует, что `metadata.zipply_tools` полезно как совместимая подсказка о зависимостях существующего навыка. Собственный инструмент требует исполняемой реализации и контракта входных данных. Его можно создать как локальный модуль в проекте и доставить через декларативный пакет с MCP. Полномочия манифестов и нативного кода относятся к хосту. Даже стандарт удалённых навыков ограничивает принятие `allowed-tools`, полученного с сервера. [Требования Skills over MCP](https://skills.extensions.modelcontextprotocol.io/specification/beta/skills#security-considerations).

## Как выглядит самообучение в рабочем сеансе

- **Hermes.** `/learn` открывает обычный агентный ход и может собрать материалы или сохранить выработанную процедуру. `skill_manage` умеет редактировать существующий навык и вспомогательные файлы. Фоновый review и Curator выполняют разные задачи. Review выделяет уроки из работы, Curator следит за библиотекой и предлагает изменения. Режим подтверждения у `skill_manage` может отправлять операции на просмотр. [Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills) · [Review в коде](https://github.com/NousResearch/hermes-agent/blob/main/agent/background_review.py) · [Curator](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator).
- **OpenClaw.** Skill Workshop поставляется как отдельный встроенный плагин с собственным каталогом обученных навыков агента. `/learn` ищет подходящую существующую процедуру и обновляет её, если это уместно. Фон имеет `off`, `propose` и `auto`. Текущий манифест указывает `auto` по умолчанию. В этом режиме Control UI показывает компактную строку Learned с возможностью отменить изменение. В `propose` можно открыть diff через Workshop или `/learn drafts`. Новый сеанс получает изменённую версию, текущий использует свой снимок. [Манифест](https://github.com/openclaw/openclaw/blob/main/extensions/skill-workshop/openclaw.plugin.json) · [Workshop](https://docs.openclaw.ai/tools/skill-workshop).
- **Claude Code.** Auto memory сохраняет небольшие заметки о проекте, предпочтениях и исправлениях в машинном каталоге репозитория. `MEMORY.md` индексирует темы, детальные записи читаются по необходимости. Навыки и плагины имеют отдельные точки установки и авторства. Сигнал «сохранена память» в интерфейсе относится к этому индексу. [Auto memory](https://code.claude.com/docs/en/memory) · [Навыки](https://code.claude.com/docs/en/skills).

У Zipply сейчас `propose_skill` создаёт черновик внутри основного запроса. Позже пользователь принимает его в библиотеке, и новый `SKILL.md` становится доступен поиску. Для сходства с Workshop нужны правка уже принятой процедуры, история применения, заметка рядом с исходной задачей и возврат к предыдущей ревизии. [Текущая реализация](../../../src/main/agent/skills/SkillProposalStore.ts).

## Проверяемые изменения для Zipply

1. **Обычный запрос к настроенному серверу.** Одна конфигурация интеграции с областью «проект» или «профиль» и актуальным статусом. Новый чат в заданной области получает доступные метаданные. `tool_search` возвращает релевантные результаты и добавляет их схемы на следующий запрос модели. Ручное прикрепление сервера остаётся доступным для выбора контекста. Критерий успеха — два разных чата одного проекта используют нужный инструмент по обычной просьбе, а чат другого проекта соблюдает границу области.
2. **Подключение при необходимости.** Один интерфейс управления в настройках, палитре и чате. Карточка вызывается только при необходимости установки, входа или изменения доступа. Показываются источник, область и состояние. Подтверждение вызова относится к конкретному инструменту, и уже согласованный допуск учитывается с привязкой к устойчивой идентичности конфигурации. DeepWiki станет одним из источников, которые использует этот маршрут.
3. **Явное обучение в чате.** «Сохрани этот способ» или `/learn` использует текущую задачу. Агент находит и открывает подходящий навык до правки. Публикация следует выбранной политике проекта. Краткая карточка в чате открывает diff, источник и отмену. Критерий успеха — следующий чат находит новую процедуру, повторное обучение обновляет её, откат возвращает прежнюю ревизию.
4. **Дополнительные инструменты и фоновое обучение.** Пакет навыка с новым инструментом поставляется через проверяемый манифест. Умение создавать код инструмента отделено от разрешения его установить и выполнить. Фоновый автор получает проверенные итоги запусков и работает с управляемыми процедурами. Сначала сравнительный прогон на новых задачах, затем настройка автоматической публикации. Skills over MCP остаётся отдельным адаптером доставки, если обнаружатся серверы, которые нужны пользователю.

У текущего прототипа стоит сохранить сервис регистрации и поиска, общий исполнитель и проверку границ. Узкое место находится в [сборке возможностей запуска](../../../src/main/agent/index.ts). Явное прикрепление сервера подаёт все схемы. Маршрут из чата держит допуск в памяти и требует дополнительного действия `load` после поиска. Эти две ветки следует свести к общей проекции разрешённых возможностей до расширения встроенного каталога.
