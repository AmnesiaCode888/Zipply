# Архитектурный дизайн: Расширение системы навыков и когнитивного протокола Zipply

## 1. Цели и назначение
Расширить систему навыков Zipply (Марии/Алисы), превратив её в полноценную библиотеку практических руководств по всем встроенным инструментам, ситуациям неопределенности («запуталась / не знаю, что делать») и типовым инженерным задачам. Внедрить в системный промпт явный рефлекс самопомощи: **навыки -> поиск в интернете -> логи/терминал -> субагенты**.

## 2. Архитектурные компоненты

### 2.1. Системный промпт (`src/main/agent/core/PromptProviders.ts`)
Внедрение в `IdentityProvider` и `SkillsProvider` четких правил:
- **Two-Tier Cognitive Routine**:
  1. **Стандартный режим**: При наличии уверенного понимания задачи — выполнение по стандартам чистого кода.
  2. **Режим выхода из тупика (Stuck & Uncertainty Protocol)**:
     - При столкновении с незнакомой библиотекой, непонятной ошибкой или неопределенностью — **первым шагом** вызвать `search_skills(query="...")` или `read_skill(skill_name="...")`.
     - Если навыков недостаточно или ошибка специфична для сторонней библиотеки/версии — **немедленно** вызвать `web_search(query="...")` и `web_fetch(url="...")` для нахождения точного фикса в интернете (GitHub Issues, StackOverflow, официальная документация).
     - При расхождении ожиданий с реальностью — проверить терминал (`terminal(action="read_terminal")`) и структуру файлов.
     - Запрет на слепые догадки и повторение неудачных действий (>2 раз подряд).

### 2.2. Библиотека встроенных навыков по инструментам (Tool Mastery)
Все навыки оформляются с валидным Frontmatter (YAML: `name`, `description`, `globs`, `triggers`, `tags`, `tools`):
1. `tool-file-mastery.md` — безопасная работа с файловой системой:
   - Хирургические правки через `SEARCH/REPLACE` (`action="edit"`).
   - Запрет полной перезаписи больших файлов (`action="write"`).
   - Чтение частями (`start_line`, `end_line`), навигация по дереву (`read_tree`, `glob`).
   - Реакция на ошибки синтаксиса и линтера (`[SYNTAX ERROR REJECTED]`, `[LINTER FEEDBACK]`).
2. `tool-terminal-mastery.md` — работа с терминалом PowerShell в Windows:
   - Синтаксис PowerShell, кодировка UTF-8, кавычки и массивы `@()`.
   - Запуск фоновых процессов (`start_background`) и отслеживание статусов.
   - Чтение открытых вкладок терминала (`read_terminal`).
   - Интерактивный ввод данных (`send_input`).
   - Безопасные неинтерактивные флаги (`-y`, `--no-interactive`).
3. `tool-grep-mastery.md` — быстрый поиск кода и символов:
   - Регулярные выражения vs строковый поиск.
   - Использование `includes` для фильтрации по расширениям.
   - Поиск определений функций, хуков, интерфейсов.
4. `tool-web-intelligence.md` — веб-разведка и поиск документации:
   - Поиск свежих версий API, breaking changes, changelog'ов.
   - Поиск точных сообщений об ошибках через `web_search`.
   - Извлечение содержимого через `web_fetch` без галлюцинаций.
5. `tool-subagents-swarm.md` — делегирование и рой агентов:
   - Роли: `architect` (проектирование), `worker` (код/тесты), `ask` (чтение/ресерч), `terminal`, `web_search`.
   - Параллельный запуск нескольких задач через массив `tasks`.
   - Синтез результатов работы субагентов.
6. `tool-skills-and-learning.md` — управление собственной базой знаний:
   - Поиск релевантных навыков через `search_skills` (векторный и текстовый поиск).
   - Чтение инструкций и вложенных файлов через `read_skill`.
   - Самоупаковка успешных сценариев через `save_skill`.
7. `tool-memory-compass.md` — долговременная память:
   - Добавление и поиск фактов, архитектурных решений и предпочтений через `manage_memory`.
   - Поддержание компактного компаса памяти.
8. `tool-mcp-integration.md` — протокол контекста модели (MCP):
   - Управление MCP-серверами через `manage_mcp`.
   - Вызов внешних инструментов через `call_mcp_tool`.
   - Разработка собственных MCP-серверов на Node.js и FastMCP (Python).
9. `tool-schedule-automation.md` — планирование и автоматизация:
   - Создание разовых таймеров и периодических cron-задач через `schedule_task`.

### 2.3. Навыки для выхода из тупика и отладки (Stuck & Troubleshooting)
1. `when-stuck.md` — пошаговый алгоритм для агента при застревании:
   - Шаг 1: Поиск в локальных навыках (`search_skills`).
   - Шаг 2: Поиск в интернете (`web_search` с точным текстом ошибки).
   - Шаг 3: Проверка реального вывода терминала и процессов.
   - Шаг 4: Декомпозиция задачи и вызов субагента для свежего взгляда.
2. `systematic-debugging.md` — строгая методология отладки:
   - 4 фазы: воспроизведение -> изоляция корня -> минимальный фикс -> верификация.
   - Принцип: доказательства перед утверждениями (evidence before assertions).
3. `web-research-troubleshooting.md` — мастерство онлайн-диагностики:
   - Формирование эффективных запросов по ошибкам компиляции, рантайма и сборки.
   - Отделение устаревших рецептов от современных решений.

### 2.4. Инженерные навыки на все случаи жизни (Engineering Defaults)
1. `test-driven-development.md` — TDD и стратегии тестирования (Vitest, Jest, Playwright).
2. `frontend-modern-web.md` — современный веб-фронтенд (React, TypeScript, CSS, Vite, Electron).
3. `backend-api-architecture.md` — проектирование надежных API (Node.js, Express/Fastify, REST, WebSocket).
4. `database-migrations-sql.md` — базы данных, Prisma, SQLite/PostgreSQL, миграции данных.
5. `performance-profiling.md` — оптимизация производительности, утечки памяти, профилирование.
6. Обновленные версии существующих навыков: `code-standards.md`, `git-workflows.md`, `docker-management.md`, `mcp-builder.md`.

### 2.5. Механизм сидинга и актуализации в `SkillService.ts`
- Создание декларативного реестра встроенных навыков (Default Skills Catalog).
- Метод `_seedDefaultSkills()` не просто проверяет 4 файла, а гарантирует наличие полного пакета стандартных навыков в директории `extraDir`.
- Добавление проверки версий / обновления встроенных навыков, чтобы при запуске приложения пользователь всегда имел актуальную библиотеку.

## 3. План тестирования и валидации
- Модульные тесты на парсинг и валидацию Frontmatter всех навыков.
- Проверка, что все созданные навыки корректно сканируются `SkillService.getAllSkills()`.
- Проверка поиска навыков по ключевым словам и триггерам через `SkillService.searchSkillsAsync()`.
- Проверка формирования системного промпта в `AgentRunner` и `PromptProviders`.
