# Дизайн-спецификация: Telegram-бот и удаленный доступ в Zipply

**Дата:** 2026-09-17  
**Статус:** Approved  
**Область:** Подсистема удаленного доступа через Telegram-бота, настройки и интеграция с агентом Zipply

---

## 1. Цель и контекст

Пользователю требуется возможность удаленно управлять Zipply со смартфона через Telegram-бота, когда он находится не у компьютера:
1. В настройках приложения добавляется отдельный раздел **«Доступ»**, в котором отображается исключительно управление **Telegram-ботом**.
2. В интерфейсе вводятся: токен бота, разрешенные ID пользователей (безопасность), переключатель запуска бота и выбор рабочей папки (проекта).
3. Бот хостится непосредственно внутри запущенного приложения Zipply (Electron Main Process) через Long Polling без сторонних тяжелых библиотек и без необходимости внешнего белого IP или ngrok.
4. Взаимодействие в боте повторяет функционал обычного чата Zipply:
   - Отправка текстовых запросов запускает агента с полным набором инструментов (файлы, терминал, поиск, память, скиллы).
   - Интерактивные инлайн-кнопки (меню, остановка задачи `[⏹ Стоп]`, выбор проектов, история).
   - Динамическое обновление/стирание кнопок при использовании (кнопка деактивируется или заменяется текстом статуса, чтобы предотвратить повторные невалидные нажатия).
   - Просмотр истории того, что делал бот (`/history`).
   - Синхронизация с сессиями Zipply: переписка и действия агента сохраняются в локальное хранилище и отображаются в приложении на ПК.

## 2. Архитектура решения

```
+------------------------------------------------------------------------+
|                          Zipply Desktop App                            |
|                                                                        |
|  [ Renderer Process ]                                                  |
|    - SettingsView -> AccessSettings.tsx (Вкладка «Доступ»)             |
|    - Sidebar.tsx (Пункт «Доступ», иконка Bot/Send)                    |
|    - Window.api.telegram IPC API                                      |
|                                                                        |
|  [ Preload Bridge ]                                                    |
|    - contextBridge.exposeInMainWorld('api', { telegram: ... })         |
|                                                                        |
|  [ Main Process ]                                                      |
|    - TelegramBotService.ts (Long Polling, Bot API client, роутер)      |
|    - AgentRunner.run('zipply', history, config, onEvent, abortSignal)  |
|    - LocalStorageService (хранилище telegram_config.json и chats.json) |
|    - IPC Handlers (telegram:start, telegram:stop, telegram:status...)   |
+------------------------------------------------------------------------+
                                  ^ | (HTTPS Long Polling)
                                  | v
                     +---------------------------+
                     |  Telegram Bot API Servers |
                     +---------------------------+
                                  ^ |
                                  | v
                       [ Telegram Mobile Client ]
```

## 3. Детали компонентов

### 3.1. Интерфейс в Настройках (`AccessSettings.tsx` & `Sidebar.tsx`)
1. **Категория в боковой панели:**
   - В `src/renderer/src/types/settings.ts` тип `SettingsTab` расширяется значением `'access'`.
   - В `Sidebar.tsx` добавляется пункт:
     ```ts
     { id: 'access', label: 'Доступ', icon: <Bot size={17} strokeWidth={1.8} /> }
     ```
   - В `TitleBar.tsx` добавляется название `access: 'Доступ'`.
2. **Представление `AccessSettings.tsx`:**
   - На странице отображается **только карточка Telegram-бота**:
     - **Статусная панель:** Индикатор (Зеленый / Желтый / Серый / Красный), имя бота (`@BotUsername`), кнопка включения/выключения («Включить бота» / «Остановить бота»), кнопка «Проверить подключение».
     - **Поле токена:** Скрытый ввод (`type="password"`) с кнопкой отображения токена, валидацией формата и ссылкой-инструкцией на `@BotFather`.
     - **Разрешенные пользователи:** Поле ввода Telegram User ID (или username), чтобы чужие пользователи не могли отдавать команды на ПК.
     - **Чекбокс автозапуска:** «Запускать бота автоматически при старте Zipply».
     - **Рабочая директория:** Выбор проекта по умолчанию для выполнения команд.

### 3.2. Сервис `TelegramBotService.ts` (Основной процесс)
- Реализуется на нативном `fetch` Node.js (Electron 33+) без добавления сторонних библиотек.
- **Методы Telegram API:**
  - `getMe()` — проверка токена и получение профиля бота.
  - `getUpdates(offset, timeout=25)` — непрерывный цикл long polling с корректным graceful shutdown через AbortController.
  - `sendMessage(chatId, text, replyMarkup)` — отправка сообщений с markdown/текстом.
  - `editMessageText(chatId, messageId, text, replyMarkup)` — обновление текста сообщений во время работы агента.
  - `editMessageReplyMarkup(chatId, messageId, replyMarkup)` — обновление/стирание инлайн-кнопок после нажатия.
  - `answerCallbackQuery(callbackQueryId, text)` — ответ на инлайн-кнопки.
  - `sendChatAction(chatId, 'typing')` — индикатор набора текста.

### 3.3. Взаимодействие с пользователем в Telegram
1. **Команды и Главное Меню:**
   - `/start` — Приветствие, информация о статусе ПК (версия Zipply, активная модель, рабочая папка) и стартовая клавиатура.
   - `/help` — Справка по всем командам.
   - `/newchat` — Сброс текущей истории диалога в боте, начало чистой сессии.
   - `/projects` — Показ списка доступных проектов с инлайн-кнопками выбора.
   - `/history` — Показ последних выполненных задач и сводки действий агента.
   - `/stop` — Остановка текущей выполняющейся задачи.
   - `/status` — Проверка состояния агента, модели и рабочей директории.
2. **Обычный ввод сообщений:**
   - Пользователь отправляет любой текст (как в обычном чате Zipply).
   - Бот создает сообщение со статусом *«⏳ Начинаю выполнение...»* и инлайн-кнопкой `[⏹ Остановить]`.
   - Во время выполнения:
     - При вызове инструментов (terminal, file, search, etc.) сообщение динамически обновляется с дебаунсом (раз в 1.5–2 сек, соблюдая лимиты Telegram).
     - По завершении отправляется итоговый ответ агента.
     - Инлайн-кнопка `[⏹ Остановить]` автоматически удаляется или заменяется на `[✅ Завершено]`, чтобы кнопки не оставались активными в старых сообщениях.
3. **Обработка инлайн-кнопок (Callback Queries):**
   - Нажатие `[⏹ Остановить]`: вызывает `abort()` на текущей задаче, обновляет сообщение на *«⏹ Выполнение прервано пользователем»*, очищает кнопки.
   - Нажатие на выбор проекта: переключает активный workspace и заменяет кнопки на `[✅ Выбран: FolderName]`.
   - Нажатие `[📜 История]`: присылает краткую выжимку последних 5 сессий.

### 3.4. Безопасность
- Если сообщение получено от Telegram User ID, которого нет в списке `allowedUsers`, бот отвечает: *«⛔ Доступ ограничен. Ваш Telegram ID: <ID>. Добавьте его в настройках Zipply на компьютере.»* и не передает запрос агенту.

### 3.5. Синхронизация с сессиями Zipply
- Каждая сессия взаимодействия в Telegram создает или обновляет сессию в `LocalStorageService.getStore('chats')` с заголовком `Telegram: [Тема]`.
- При переключении за ПК пользователь видит диалог в общем списке диалогов Zipply с полным отображением всех инструментов и сообщений.
