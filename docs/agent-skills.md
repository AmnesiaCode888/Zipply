# Навыки агента Zipply

Навык — переносимый пакет с `SKILL.md`, YAML frontmatter и необязательными справочными файлами. Zipply сначала ищет по названию и описанию, затем загружает инструкции и только нужные файлы для выбранной задачи. Навык может ссылаться на инструменты Zipply, но сам пакет не устанавливает плагин, не добавляет новый MCP-сервер и не выдаёт разрешения.

## Формат

```md
---
name: review-typescript-change
description: Проверяет небольшое изменение TypeScript и выбирает полезные локальные проверки.
metadata:
  zipply_tools: "core:search_project core:read_files core:code_intelligence"
---

# Проверка изменения TypeScript

Используй этот процесс, когда пользователь просит проверить изменение в проекте.

1. Найди затронутые файлы и прочти относящиеся к ним инструкции проекта.
2. Проследи поведение от места изменения к вызывающему коду.
3. Запусти проверки, подходящие проекту и разрешениям текущего запуска.
4. Сообщи о находках первыми, указав файл и участок кода; отдели подтверждённые проблемы от вопросов.
```

Поддерживаемые frontmatter:

- `name`: 1–64 строчных латинских букв, цифр и одиночных разделительных дефисов; у загруженных Agent Skills имя совпадает с именем каталога.
- `description`: непустое описание до 1024 символов, включая задачу и условие применимости.
- `disable-model-invocation: true`: скрывает навык от автоматического поиска модели.
- `user-invocable: false`: отключает ручной вызов из UI.
- `metadata.zipply_tools`: строка со ссылками через пробел. Поле Zipply-специфично; прочие приложения могут его игнорировать.

Пиши процедуру коротко и проверяемо. Указывай, когда её применять, нужные входы, последовательность шагов, способ проверки и что делать при неудаче. Не сохраняй секреты, личные данные, случайный вывод инструментов или сведения об одноразовой задаче.

## Связанные инструменты

Формат ссылки — `тип:идентификатор`:

| Ссылка | Пример | Что сделает Zipply |
| --- | --- | --- |
| Встроенный инструмент | `core:search_project` | Использует инструмент, уже доступный выбранному агенту. |
| Инструмент плагина | `plugin:cybersec/cybersec_audit_project` | Подключает инструмент установленного плагина к текущему запуску. Имя плагина и инструмента берутся из каталога Zipply. |
| Инструмент MCP | `mcp:<server-id>/<tool-id-from-search_tools>` | Подключает найденный инструмент выбранного сервера MCP. Второй сегмент — точный ID инструмента из `search_tools`, а не его удалённое отображаемое имя. |

Ссылки помогают найти и загрузить инструменты. Плагин должен быть установлен. MCP-ссылка работает только с уже настроенным сервером профиля; при загрузке навыка Zipply может подключить только сохранённый удалённый HTTP-сервер, а локальные stdio-процессы и новые серверы автоматически не запускает. В режиме только для чтения MCP-вызовы недоступны. В остальных режимах вызов инструмента проходит через действующую политику; в полном доступе повторное подтверждение для каждого MCP-вызова отключено. Доверие в режиме подтверждений ограничено конфигурацией сервера и fingerprint конкретной схемы инструмента.

Перед применением модель видит список доступных навыков (`<available_skills>`) с названиями, описаниями и каталогами прямо в контексте, а при необходимости может дополнительно искать через `search_skills`. Чтобы применить подходящий навык, модель загружает его через `load_skill` (по имени или ID), получая инструкции, список файлов внутри пакета и доступ к чтению файлов внутри каталога навыка. Каталог обновляется динамически, поэтому только что установленный или созданный навык можно сразу загрузить в этом же запуске. `search_tools` ищет встроенные, установленные плагинные и настроенные MCP-возможности, подключая максимум три наиболее подходящих удалённых HTTP-сервера профиля.

Чтобы найти и установить навык из каталога `skills.sh`, можно попросить агента «найди навык для X» или «скачай навык для X» — агент вызовет `install_skill(action="search")`, затем `install_skill(action="install")` и сразу применит навык без лишних окон подтверждения. Библиотека также читает каталоги `~/.agents/skills`, `~/.claude/skills`, проектные `.agents/skills` / `.claude/skills` и Zipply userData.

`skills.sh` — пока единственный удалённый источник поиска; подключение каталогов отделено интерфейсом `SkillSourceProvider`, поэтому новый каталог не требует менять tool-контракт агента.

Новый MCP-сервер можно найти через `manage_mcp(action="search")` и подключить через `manage_mcp(action="install")`; адрес сервера показывается отдельно. Установка нового внешнего сервера и передача авторизации остаются отдельными решениями. Уже настроенные серверы принадлежат профилю пользователя и доступны из других чатов. [Документация DeepWiki](https://docs.devin.ai/work-with-devin/deepwiki-mcp).

## Создание и обновление навыков

Модель может создавать и обновлять активные навыки напрямую через `save_skill` (без черновиков и ручного подтверждения) в `.agents/skills/<name>/SKILL.md` проекта или в `~/.agents/skills/<name>/SKILL.md` профиля пользователя. Новый навык сразу активен и доступен через `load_skill`.

В Zipply процедуры принадлежат навыкам; факты и предпочтения относятся к отдельному слою памяти; правила конкретного репозитория — его `AGENTS.md` и документации. Не превращай кратковременные факты проекта в универсальный навык.
