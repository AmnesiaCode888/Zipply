# Базы данных, SQL и Миграции

## 1. Проектирование реляционных схем:
- **Первичные ключи**: Используй целочисленные автоинкрементные ID или детерминированные UUID/CUID.
- **Индексы**: Добавляй индексы (`CREATE INDEX`) на внешние ключи (Foreign Keys) и колонки, по которым регулярно выполняется фильтрация (`WHERE`) или сортировка (`ORDER BY`).
- **Связи**: Явно определяй каскадные удаления (`ON DELETE CASCADE`) или ограничения (`RESTRICT`).

## 2. Безопасные миграции:
- Никогда не применяй деструктивные миграции (`DROP TABLE`, `DROP COLUMN`) на рабочих данных без предварительного резервного копирования (backup).
- Двухфазное удаление колонок:
  1. Сначала перестань использовать колонку в коде приложения.
  2. Отдельной миграцией удали саму колонку из схемы базы данных.

## 3. Защита от SQL-инъекций:
- ВСЕГДА используй параметризованные запросы (`db.prepare("SELECT * FROM users WHERE id = ?").get(id)`) или возможности ORM. Категорически запрещено конкатенировать строки в SQL запросы!
