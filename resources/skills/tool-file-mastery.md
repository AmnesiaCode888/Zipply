# Мастерство работы с инструментом `file`

Инструмент `file` — главный инструмент агента для навигации по проекту и внесения изменений.

## 1. Золотое правило: Чтение перед модификацией
НИКОГДА не пытайся редактировать или создавать похожий файл, не изучив сначала его реальное содержимое.
- Для больших файлов ВСЕГДА используй пагинацию: `file(action="read", path="...", start_line=1, end_line=150)`.
- Номера строк в выводе (например, `42: `) служат ТОЛЬКО для твоей ориентации. **Никогда не копируй префиксы `42: ` в блоки замены!**

## 2. Хирургические правки через SEARCH / REPLACE (Anti-Truncation SOTA)
Для модификации существующих файлов ВСЕГДА используй `action="edit"`.
- **СТРОГО ЗАПРЕЩЕНО** перезаписывать существующие файлы (>50 строк) через `action="write"` — это приводит к случайному удалению логики и усечению кода (truncation).
- Если нужно изменить несколько мест в одном файле, отправь один вызов `file(action="edit")` с несколькими блоками:

```
<<<<<<< SEARCH
const oldVariable = 10
=======
const oldVariable = 20
>>>>>>>
<<<<<<< SEARCH
function handleAction() {
  doOldThing()
}
=======
function handleAction() {
  doNewThing()
}
>>>>>>>
```

## 3. Требования к блоку SEARCH
- Блок `SEARCH` должен **символ-в-символ** совпадать с существующим содержимым (включая отступы, табы и пробелы).
- Включай в блок SEARCH 2-3 строки контекста до и после изменяемого участка для однозначной привязки.

## 4. Реакция на диагностику и линтер (Self-Healing)
- Если в ответе инструмента вернулся `[SYNTAX ERROR REJECTED 🛑]` или `[LINTER FEEDBACK ⚠️]`:
  1. Не игнорируй сообщение! Твоя правка могла быть отклонена защитой от повреждения кода.
  2. Внимательно прочти ошибку AST или TypeScript (например: "Unclosed JSX element", "Missing semicolon", "Duplicate identifier").
  3. В следующем же шаге пришли исправленный блок `action="edit"`.

## 5. Поиск и дерево
- `file(action="glob", pattern="**/*.tsx")` — поиск файлов по маске.
- `file(action="read_tree", max_depth=3)` — быстрый обзор структуры директорий.
