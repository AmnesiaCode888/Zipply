# Протокол выхода из тупика (When Stuck / Perplexity Recovery)

Если ты запуталась, задача кажется непонятной, код падает с ошибкой, а предыдущая попытка фикса не сработала — **ОСТАНОВИСЬ**. 
Категорически запрещено повторять аналогичные неудачные правки (Anti-Thrashing Rule). 

Следуй строгому 4-уровневому протоколу самопомощи:

```
               [ОШИБКА / НЕОПРЕДЕЛЕННОСТЬ / ТУПИК]
                                |
             1. Проверить библиотеку навыков Zipply
                    search_skills(query="...")
                                |
        Найдено решение? --- ДА ---> read_skill() -> Выполнить
                                |
                               НЕТ
                                |
             2. Поиск в интернете (Web Intelligence)
             web_search("точный текст ошибки библиотека")
                                |
        Найдено решение? --- ДА ---> web_fetch() -> Точечный фикс
                                |
                               НЕТ
                                |
             3. Инспекция реального окружения
           terminal(action="read_terminal") / логи
                                |
             4. Декомпозиция или субагент
        ask_agent(agent_id="architect" / "ask")
```

## Уровень 1: Поиск по встроенным навыкам
В Zipply встроены десятки готовых инструкций. Сформулируй тему проблемы и запусти поиск:
`search_skills(query="как настроить sqlite electron")` или `search_skills(query="systematic-debugging")`.
Если найден подходящий навык — прочитай его через `read_skill(skill_name="...")`.

## Уровень 2: Поиск свежего решения в вебе
Если проблема связана со сторонней библиотекой, версионным конфликтом или специфической ошибкой компилятора:
1. Скопируй **точный текст ошибки** (без специфичных путей твоей файловой системы).
2. Добавь название библиотеки и версию.
3. Вызови `web_search(query=' "vite" "cannot resolve import" tsconfig paths ')`.
4. Перейди по ссылке на GitHub Issue или StackOverflow через `web_fetch`. В 95% случаев кто-то уже решал эту проблему.

## Уровень 3: Проверка реального состояния терминала и окружения
Часто агент строит ложные предположения, потому что не видит реального вывода процесса.
- Вызови `terminal(action="read_terminal")` — посмотри полный стек трейс, warning'и и код выхода.
- Проверь реальные версии в `package.json` или `requirements.txt`.

## Уровень 4: Декомпозиция и смена точки зрения
Если решение всё ещё не найдено:
- Не пытайся решить задачу целиком одним махом. Разбей её на 3 элементарных подзадачи.
- Делегируй проверку субагенту: `ask_agent(agent_id="ask", prompt="Проанализируй, почему падает функция X в модуле Y")`. Субагент запустится со свежим контекстом и без предвзятости предыдущих шагов.
